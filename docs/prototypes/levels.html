    RFC 6570 URI templates for .NET

    Clear every level of URI templates.

    RFC 6570 defines four levels of URI template, each one harder than the last. Chatter.Rest.UriTemplates implements all four. Play through the levels to see what each one adds and how the engine handles it.

    →/users/42?fields=name&fields=email

    Tutorial · why templates

    String concatenation fails quietly.

    Building a URL by hand works until a value contains a space, an ampersand, or nothing at all. The result is still a string. It is just the wrong one, and nothing tells you.

    By hand Interpolation

    var url = $"/search?q={q}&lang={lang}";
// q = "tea & cake", lang = null
    /search?q=tea & cake&lang=
    • The & inside the value starts a new parameter.
    • The spaces are not encoded.
    • A missing lang still leaves lang= behind.

    Template RFC 6570

    var url = new UriTemplate("/search{?q,lang}")
    .Expand(("q", "tea & cake"));
    /search?q=tea%20%26%20cake
    • The value is percent-encoded for its position.
    • Separators come from the template, not from you.
    • Undefined variables drop out cleanly.
    1

    Level 1 · simple string expansion

    Swap in a value, safely.

    The simplest expression is a variable name in braces. Its value is percent-encoded so that only unreserved characters survive as they are: letters, digits, and - . _ ~.

    • {x} simple string
    2

    Level 2 · reserved and fragment

    Let reserved characters through.

    Sometimes a value is already part of a URI, like a path. The + operator keeps reserved characters such as / and ? as they are. The # operator does the same and adds a fragment marker.

    • + reserved
    • # fragment
    3

    Level 3 · multiple variables and operators

    Many variables, five new operators.

    An expression can now hold several variables, and each operator knows where it belongs in a URI: which character to start with, what to join with, and whether to write name=value. Undefined variables simply drop out.

    • . label
    • / path segment
    • ; path parameter
    • ? query
    • & query continuation
    4

    Level 4 · value modifiers

    Shape the values themselves.

    Two modifiers change how a value expands. :N keeps the first N characters of a string. * explodes a list or an associative array into one item per separator. Composite values can be passed directly or built with UriTemplateValue.From.

    • :N prefix
    • * explode
    ∞

    Final stage · the engine

    One pipeline beats every level.

    Whatever the level, a template goes through the same four steps. The hard work happens once, up front, so expanding is fast and predictable.

    1

    Parse once

    The template is parsed when you construct it. A malformed one such as {??x} throws a FormatException right there, never later inside Expand.

    2

    Tokenize

    Parsing yields literal tokens and expression tokens. Each expression carries its operator and its variables, with any prefix or explode modifier.

    3

    Pick a strategy

    Every operator has its own strategy that knows its first character, its separator, and whether it names its values.

    4

    Encode

    Values are percent-encoded per RFC 3986: unreserved characters only, or reserved ones too for + and #.

    Loot · two packages

    Take the engine with you.

    The engine ships on its own. If your app uses dependency injection, a small companion package registers it for you.

    Core

    Chatter.Rest.UriTemplates

    The parser, the operator strategies, and the encoder. Construct a UriTemplate, call Expand, get a URI.

    var t = new UriTemplate("/orders{?status,page}");
t.Expand(("status", "shipped"), ("page", "2"));
// /orders?status=shipped&page=2
    • CoverageRFC 6570 levels 1 to 4
    • DependenciesNone
    • Runs on.NET Standard 2.0 and modern .NET
    Companion

    Chatter.Rest.UriTemplates.DependencyInjection

    One call registers the parser and a template factory. Inject IUriTemplateFactory wherever you build links.

    services.AddUriTemplates();

// in any class that takes IUriTemplateFactory
var t = factory.Create("/orders/{id}");
    • AddsAddUriTemplates()
    • InjectsIUriTemplateFactory
    • LifetimeSafe to call more than once

    Continue?

    Install in one command.

    Add the package and expand your first template. Lists, dictionaries, and every operator work the same way.

    Install

    dotnet add package Chatter.Rest.UriTemplates

    Using DI too? Add Chatter.Rest.UriTemplates.DependencyInjection.

    First expansion

    using Chatter.Rest.UriTemplates;

var template = new UriTemplate("/orders{?status,page}");
var uri = template.Expand(new Dictionary<string, string>
{
    ["status"] = "shipped",
    ["page"] = "2"
});
// /orders?status=shipped&page=2
